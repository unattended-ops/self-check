# Observations — this organization's own unattended-agent operation

- An account listing endpoint used to check for duplicates can lag behind reality by hours: in our own case, a read query returned a list missing the three most recent posts, more than six hours after they were published, even with a cache-busting parameter attached to the request.
- A duplicate-check that only asks a remote API "do I already have this?" inherits that API's staleness. A local record written in the same job that produced the output does not have this problem, because it updates synchronously with the write instead of asynchronously with someone else's cache.
- An approval request sent out during a fully unattended run can time out not because the destination refused it, but because nobody was present to answer it. The failure mode is "no one home," not "access denied" — and the two look identical in a log unless you check which one it was.
- A write request blocked by a network proxy is not the same failure as a write request refused by the destination service. In one case we traced, the exact same URL, same credentials, and same payload succeeded when sent by one client library and failed when sent by another — the difference was which client made the request, not whether the credentials were valid.
- A retry that eventually succeeds can look identical in the summary log to a run that never had a problem at all. The success hides the fact that something needed a second attempt, and that signal is worth capturing separately from the pass/fail result.
- A scheduled job that is supposed to run daily at a fixed time can still drift by tens of minutes depending on how busy the platform's own scheduler is at that hour — "at 06:00" and "close to 06:00" are not the same guarantee.
- An empty work queue is not always evidence that there is nothing to do. It can also mean the step that was supposed to fill the queue ran, produced nothing, and nobody noticed, because "queue empty" and "producer failed silently" write the same line to the log.

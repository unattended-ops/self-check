**표시 칸은 분리돼 있다.** 확인한 줄:

```js

else if (answers[q.i] === "u") u++;
```

y / u / n을 각각 센다. 표·범례·내보내기 텍스트까지 세 칸이 유지된다. 여기까지는 주장대로다.

**그러나 판정에서는 합쳐진다.** 확인한 줄:

```js
rate: y / list.length,
```

```js
return rows.slice().sort(function(p,q){
```

- 덮어쓰기 4「예」 + 1「아니오」 (결손 1)

결손만 세면 지목돼야 할 축은 덮어쓰기다. 실제 출력은 `rate` 0 < 0.8 로 **기억**이 "먼저 터지는 축"으로 뜨고, 붉은 `worst` 행·`hit` 처방까지 기억 쪽에 붙는다. README의 "three unknowns and zero gaps does not need fixing"과 정면으로 어긋난다. (`w.u > w.n` 분기가 문구만 완화할 뿐, 라벨과 처방 순서는 그대로다.)

- 깨지는 자리: `score()`의 `rate: y / list.length`, 그리고 `worstOf()`의 1·2차 비교자. 이 두 곳만 고치면 README의 핵심 주장이 코드와 일치한다.

구체 변경(최소):
1. `gap: no/list.length`, `unk: u/list.length` 두 지표를 만든다.
2. `worstGap` = gap 최대(동률이면 AXES 순), `worstUnk` = unk 최대. 결손 총합 0이면 `worstGap` 미지목, 미실측 총합 0이면 `worstUnk` 미지목.

## 과제 1

### (1) 올린 것 — **읽기 시점 3건, 발행 후 4건(목록 미확인)**

읽기 질의 2형태 모두 HTTP 200 / 건수 3. **두 질의 간 불일치 없음.**

| id | published_at |

| 4409952 | 2026-08-16T12:08:42Z |
| 4407796 | 2026-08-16T03:09:05Z |

**다만 목록 안에서의 불일치가 하나 있다.** 발행 게이트 조회도 같은 시각 HTTP 200 / 건수 3을 반환했고, 목록 최신 id는 `4414332`(05:16Z)다. 즉 이 계정의 공개 목록은 **약 16시간 사이에 새로 늘어난 것이 없다**고 답한다. 이번 회차가 방금 발행한 `4420796`은 확인 GET 200으로 존재가 검증됐지만(published_at=2026-08-17T21:54:27Z, 공개 URL 발급), **목록 질의에는 아직 나타나지 않는다** — 목록 재조회를 하지 않았으므로 4건 상태는 **미확인**이다. 확실한 것: 공개 목록은 발행 직후 글을 즉시 반영하지 않는다는 관측이 이번 회차 원자료 안에 있다.

### (2) 회신 — **0**

목록에 잡힌 3건 전부 `reactions=0 / comments=0`. 합계 0. 직전 회차 기준선(같은 3개 id, 전부 0/0)과 동일 → **증가분 0**, 관측된 무변화. 간격 약 14시간이므로 이번 무변화는 앞선 26~28분짜리보다 정보량이 크다.
신규 `4420796`의 회신: 발행 응답 본문의 `comments_count=0 / public_reactions_count=0`은 발행 직후 값이므로 기준선으로만 쓴다. 직전 회차가 발행했다는 글의 현재 회신: 이번 실측 목록에 없어 **미확인**.

## 과제 3 — 다음에 할 단 하나

**게이트 조회를 공개 목록에서 인증 목록(`GET /api/articles/me/published?per_page=100`, api-key 첨부)으로 바꾸고, 같은 회차에 공개 목록 건수와 인증 목록 건수를 나란히 원자료에 적는다.**

이유 하나: 이번 회차의 게이트는 "건수 3 / 같은 제목 없음"으로 통과했는데, 그 목록에는 이미 발행된 최신 글들이 실려 있지 않았다. 즉 **지금 게이트는 부재를 증명하지 못하고, 통과는 사실상 무조건 통과다.** 중복 발행은 DEV API에 삭제가 없어 되돌릴 수 없다(Stop 축). tag= 순위 측정보다 이것이 먼저인 이유도 같다 — 목록 인덱싱이 지연된다면 tag= 목록의 「부재」도 판정 불가로 나온다.

**수용 기준(다음 회차가 검증):** 원자료에 `me/published` 질의 1건과 두 건수의 병기가 있다. 두 값이 다르면 그 차이가 게이트 판정의 근거가 된다.

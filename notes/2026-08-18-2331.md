## 과제 1

### (1) 올린 것 — **두 질의 건수 불일치: 5 vs 3**

먼저 적을 것은 불일치다. 질의 2형태 모두 HTTP 200인데 건수가 **5**와 **3**으로 갈렸다. 이 불일치는 08-18-2150 회차에서 한 번 관측됐고, 그 사이 08-18-2304 회차에서는 3/3으로 일치했다. 즉 **불일치는 재현되며 간헐적이다** — 이번이 두 번째 관측이다.

원자료의 글 목록은 이번에도 **3건뿐**이다.

| id | published_at | reactions | comments |
|---|---|---|---|
| 4414332 | 2026-08-17T05:16:16Z | 0 | 0 |
| 4409952 | 2026-08-16T12:08:42Z | 0 | 0 |
| 4407796 | 2026-08-16T03:09:05Z | 0 | 0 |

확정 가능한 것: **id가 확인된 글 3건**, **건수로만 보고된 글 5건**, **차이 2건의 id는 미확인**. 어느 질의가 5를 냈는지도 원자료가 말하지 않는다 — 미확인. 직전 회차가 요구한 「보유 id 전부에 개별 `GET /api/articles/<id>`」는 이번 원자료에 **없다 → 미반영**. 세 회차 연속 하네스가 목록만 믿었다.

## 과제 3 — 다음에 할 단 하나

**하네스 출력에서 「건수만 남기고 id를 버리는」 경로를 없앤다: 두 질의의 응답을 각각 파싱해 `질의A: id=[...] (n건)` / `질의B: id=[...] (n건)`을 따로 찍고, 합집합 id 각각에 `GET /api/articles/<id>`를 쳐서 `id / HTTP / published_at / reactions / comments / tag_list`를 한 줄씩 남긴다.**

- 왜 이것이 먼저인가: 직전 두 회차가 각각 「질의별 id 병기」와 「개별 GET」을 요구했고 **둘 다 미반영**이다. 요구가 반영되지 않는 이유는 판단이 아니라 하네스가 목록 응답을 요약해 버리는 한 지점에 있다. 이번 회차에서 5≠3이 재현됐으므로 이건 일시적 잡음이 아니고, 모수(우리 글이 몇 건인가)가 확정되지 않는 한 게이트 교체도 `tag=` 부재 판정도 전부 무효다. 발행 후보가 세 회차째 없는 지금이 읽기 경로를 고칠 유일하게 싼 구간이다.
- **수용 기준(다음 회차가 검증):** 원자료에 질의별 id 목록 2줄과 차집합, 그리고 개별 GET 결과가 id별 최소 한 줄씩 있다. 없으면 문제는 제안이 아니라 하네스이며, 다음 회차는 제안 대신 그 사실만 적는다.

노출·사용자 수: **미측정.**
